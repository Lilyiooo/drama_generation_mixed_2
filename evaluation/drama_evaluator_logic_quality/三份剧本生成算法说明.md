# 三份剧本生成算法说明

记录日期：2026-09-16。根据实际运行配置和模型调用记录核对。

## 共同输入与实验范围

三份结果均完成60集，使用同一份八字段逐集大纲：

`/inspire/hdd/global_user/hesiyang-CZXS25210137/drama_operator_new_v9_future5_state2_complete/drama_operator_new_v9_future5_state2_complete_simple/output/qwen36_27b_eight_fields_demo_20260916_060508_407704`

该大纲是三轮评审重写中选出的88分版本；88分是当时模型对大纲的评分，不是这三份完整剧本的评分。

三份均使用本地部署的Qwen模型（服务名 `qwen-local`），每集生成提示词目标为1000～1400字。该目标不是严格长度保证，实际正文会有差异。

本次比较从已有逐集大纲开始，未分别重跑创意、详细大纲和逐集大纲生成。因此不能直接当作“创意到完整剧本”的端到端对照。

## 算法对照

| 项目 | baseline | pipeline1 | pipeline2 |
|---|---|---|---|
| 历史信息 | 前面所有集完整正文 | 原有叙事记忆流程 | 原有叙事记忆流程 |
| 未来需求树、逐集贡献映射 | 无 | 有 | 有 |
| Event Graph / World State | 无 | 有 | 有 |
| 场次大纲 | 无，直接写整集 | 先生成场次大纲，再写整集 | 先生成场次大纲，再写整集 |
| 生成后衔接调整 | 无 | 开启 | 关闭 |
| 生成后字数及台词比例调整 | 无 | 开启，按检查结果触发 | 关闭 |
| 评测命令中的名称 | `baseline` | `pipeline1` | `pipeline2` |

## baseline：全部历史正文作为上下文

每集输入故事背景、当前集大纲和此前所有集的完整正文，一次调用生成当前集。既往正文按集号累计，不摘要、不筛选、不截断；没有状态抽取、需求树、场次大纲和后处理润色。

本次确实设置了 `--min-chars 1000 --max-chars 1400`，不是早先1200～2200字的那次baseline。

## pipeline1：原有记忆算法，开启后处理

先根据全剧逐集大纲生成未来需求树与逐集贡献映射。逐集结合大纲、叙事记忆和前文上下文生成场次大纲，再生成整集正文。随后进行与前文的衔接调整，以及按需进行字数和台词比例调整；最终正文落盘，并更新原有叙事记忆供后续集使用。

运行记录确认：整集正文调用60次，衔接调整调用59次，字数/台词比例调整调用39次。这里是对应模型请求记录数，不是语义问题数量；调用衔接调整并不代表先检测到了冲突。

## pipeline2：原有记忆算法，关闭后处理

使用同类未来需求树、逐集贡献映射和Event Graph / World State记忆流程，仍然先生成场次大纲，再生成整集正文。

运行配置明确保存 `adjust_word_count=false`、`adjust_coherence=false`，且未发现两类调整调用。正文生成后直接进入保存及记忆更新流程。

## 评测入口与结果

在本文件所在目录运行：

```bash
bash run_local_three_scripts.sh baseline
bash run_local_three_scripts.sh pipeline1
bash run_local_three_scripts.sh pipeline2
```

默认结果分别位于 `output/three_scripts_qwen-local/{baseline,pipeline1,pipeline2}/`，查看 `scores.json` 和 `00_多Agent评估报告.md`。合并后的评测输入位于同一结果根目录的 `inputs/`。

三组均采用同一评测流程和默认模型配置；本说明不包含尚未核实的评测分数。

## 比较时的解释边界

- baseline与pipeline2虽然都没有后处理，但场次规划、正文提示词、输入组织等仍不同，因此不是只替换记忆方式的严格单变量实验。
- pipeline1与pipeline2是独立重新生成的两条轨迹，并非同一份原始正文的后处理前后对照；差异不能全部归因于后处理。
- 字数目标相同不代表实际长度相同，比较质量时应同时报告实际长度。评测导出全文（含统一集标题及空白）分别为88779、84371、79311字符。
